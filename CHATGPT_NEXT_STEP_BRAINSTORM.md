Use this file as a prompt for an external ChatGPT-style brainstorming pass. The goal is to propose next algorithm improvements for the current compact beam + QUBO CPMP solver.

## Prompt To External ChatGPT

You are helping improve a CPMP / container pre-marshalling solver. The current promoted research line is a compact byte-state beam search with a small QUBO quality-diversity selector and macro future credit v2. QUBO only selects among legal child states generated by classical search. It does not generate crane moves.

Please propose ablation-friendly next-step ideas that can improve both:

1. open120 DLTS 5x5/7x5 results; and
2. paper BF/CV sample-set results.

Important constraints:

- Do not propose deep learning or trained policies.
- Do not propose running multiple solvers as a fallback portfolio.
- Do not propose case-name-specific gates.
- Do not turn BS-FRG into a fallback solver.
- Prefer interpretable mechanisms that can be switched on/off and tested.
- Any proposed mechanism should preserve legal move generation and validator replay.
- Any candidate must be paired against `qubo_scheduler_state_v5_qubo_diversity_union_macro_credit_v2_polish`.

Please return:

1. the top 5 ideas, ranked by expected value and risk;
2. a short mechanism sketch for each idea;
3. what telemetry would prove or disprove it;
4. the smallest ablation experiment to test it;
5. pseudocode for the best idea.

## Latest Mechanism Result To Explain

Macro future credit v2 is stronger than v1 because it avoids rewarding macro candidates that only have receiver debt:

- completion witness and macro-path evidence create positive credit;
- receiver debt subtracts from credit;
- high debt without witness is penalized;
- positive macro credit is capped.

Parameter sweeps did not beat the defaults:

| sweep | paper sample1 result |
|---|---|
| default v2 | `56/62`, penalty `4437` |
| `receiver_debt_penalty_weight=12` | `52/62`, penalty `5452` |
| `min_witness_quality=0.25` | `54/62`, penalty `5034` |

Do not propose simply increasing/decreasing the same credit weights. The next improvement probably needs better candidate evidence, lineage survival, or mode separation.

## Strong Hypotheses

### 1. Credit is useful, but witness quality is still shallow

The current witness says a macro candidate has future promise, but it does not yet measure whether that promise survives several beam layers. A next profile should score completion witness quality by downstream survival or short proof chains, not just immediate macro metadata.

### 2. BF and CV need different diagnostics, not different hardcoded gates

BF hard cases expose recovery-chain retention under time pressure. CV hard cases expose candidate absence, path debt, and lineage collapse. The mechanism should be structural, not case-name based.

### 3. Candidate generation and lineage quality must be measured separately

A next profile should record:

- useful child absent;
- useful child generated but not selected;
- useful child selected but trapped in a dead lineage;
- selected route reaches `N=0` only through an over-cap or long path.

## Candidate Idea Menu

### Idea A: Witness survival credit

Give macro candidates additional credit only if similar witness-bearing candidates survive for several layers or repeatedly lower `n` without increasing path debt.

Small test: BF14/BF30 plus open residual pair.

### Idea B: CV candidate-universe probe

For CV/5-4, CV/10-6, and CV/10-10, trace whether any legal candidate can reduce `n` within the first few layers. If useful candidates are absent, improve generation; if present but dropped, improve QUBO selection.

Small test: trace-only first, then one generation or selection ablation.

### Idea C: Short recovery-chain retention reserve

Reserve a tiny beam quota for short, witnessed macro chains only when they are both low-debt and source-scarcity aware. This should be expressed as QUBO selection pressure or a bounded reserve, not a fallback path.

Small test: BF14/BF30/BF32 and open120 residuals.

### Idea D: Path-debt near-tie veto

Use receiver debt as a near-tie veto only when candidates have similar `n`, depth, and witness quality. Avoid broad linear debt penalties.

Small test: CV/6-6 and CV/5-9 controls.

### Idea E: Final-lineage dashboard

Before adding more logic, summarize which selected candidates survive for multiple layers and which feature families appear on final paths. Use this to decide whether the next intervention should be generation, selection, or lineage repair.

Small test: six current sample1 failures plus open120 paired references.
