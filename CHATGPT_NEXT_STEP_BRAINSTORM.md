# Brainstorm Brief For Next Algorithm Ideas

Date: 2026-06-29

Use this file as a prompt for an external ChatGPT-style brainstorming pass. The goal is to propose next algorithm improvements for the current compact beam + QUBO CPMP solver.

## Prompt To External ChatGPT

You are helping improve a CPMP / container pre-marshalling solver. The current best research line is a compact byte-state beam search with a small QUBO quality-diversity selector. QUBO only selects among legal child states generated by classical search. It does not generate crane moves.

Please propose ablation-friendly next-step ideas that can improve both:

1. open120 DLTS 5x5/7x5 results; and
2. paper BF/CV sample-set results.

Important constraints:

- Do not propose deep learning or trained policies.
- Do not propose running multiple solvers as a fallback portfolio.
- Do not propose case-name-specific gates.
- Do not turn BS-FRG into a fallback solver.
- Prefer interpretable mechanisms that can be switched on/off and tested.
- Any proposed mechanism should preserve legal move generation and validator replay.
- Any candidate must be paired against `qubo_scheduler_state_v5_qubo_diversity_union_polish`.

Please return:

1. the top 5 ideas, ranked by expected value and risk;
2. a short mechanism sketch for each idea;
3. what telemetry would prove or disprove it;
4. the smallest ablation experiment to test it;
5. pseudocode for the best idea.

## Hard-Case Mechanism Split

Seven traced hard/regression cases show different mechanisms:

| case class | observed behavior | implication |
|---|---|---|
| BF14/BF32 | compact union lacks short BS-FRG recovery; long FRG seed paths can reach `N=0` but over cap/time | need short recovery-basin access, not long fallback acceptance |
| CV 5-8 / 6-6 | local micro/debt signals can turn good compact paths into long feasible routes | need path-debt guard and route-quality preservation |
| CV 10-6 | search reaches low `n` but dies in retained lineage | need basin escape before final low-n collapse |
| CV 10-10 | candidate pools are large but `n` barely drops | need candidate-universe change or long-horizon recovery-state generation |

## Strong Hypotheses

### 1. One scalar debt score is not enough

Receiver debt and escape potential are real signals, but they should probably be separated by failure mode:

- guard compact routes that are already in a good basin;
- search for missing recovery basins only when the current basin is provably bad;
- avoid rewarding long FRG seed paths as if they were quality wins.

### 2. Candidate generation and lineage quality must be measured separately

A next profile should record:

- useful child absent;
- useful child generated but not selected;
- useful child selected but trapped in a dead lineage;
- selected route reaches `N=0` only through an over-cap path.

### 3. BF and CV should not be merged during diagnosis

The three-set scorecard exists because combined BF+CV totals can hide damage:

- BF hard cases expose deep recovery and long seed-path issues;
- CV hard cases expose path-debt and basin-collapse issues;
- a profile that helps only one side remains an ablation.

## Candidate Idea Menu

### Idea A: Mode-split debt guard

Use receiver-debt only as a near-tie veto when the compact route is already making clean progress. Do not use it as a broad linear term in high-uncertainty layers.

Small test: CV 5-8 / 6-6 controls plus paper sample10 CV.

### Idea B: Basin escape trigger

Add a trace-derived trigger for low-n dead basins: activate extra basin diversity only after repeated selected lineages reach low `n` without terminal progress.

Small test: CV 10-6 and open residual `5x5_cv2_test_10`.

### Idea C: Short recovery-chain supplement

Generate a tiny number of short reduction-chain children only when the candidate universe barely lowers `n` despite large candidate counts.

Small test: CV 10-10 and BF32; verify the generated child enters the normal candidate pool and does not graft a fallback solution.

### Idea D: FRG seed quality filter

Keep FRG seed materialization for reproducibility, but distinguish long feasibility-only seed paths from quality recovery paths. A seed path over cap should be telemetry, not promotion evidence.

Small test: BF14/BF32 strict hard-family rows.

### Idea E: Survivor ancestry dashboard

Before adding more logic, summarize which selected candidates survive for multiple layers and which feature families appear on final paths. Use this to decide whether the next intervention should be generation, selection, or lineage repair.

Small test: seven hard cases plus open residual pair.

## Recommended First Experiment

Start with Idea A plus Idea B:


- BF and CV metrics are reported separately.
