# chen_greedy_algorithm 说明

## 问题定义

当前主问题是跨堆/跨贝顶箱搬移：

- 只能搬某堆最上方的箱。
- 只能放到另一堆的最上方。
- 源堆和目标堆不能相同。
- 不允许同堆内重排层位。
- 目标堆高度不能超过 `H=6`。

## 逆序箱数 `N(Future)`

对单堆从第 2 层向上检查，寻找第一处：

```text
上层关序号 > 下层关序号
```

找到后，将该层及其上方所有非空箱计入逆序箱数。

若不存在这种相邻层违例，则该堆逆序箱数为 0。

全场逆序箱数为所有堆逆序箱数之和。

## 综合指标 `G`

```text
G = 已执行搬箱步数 + N(Future)
```

硬约束：

```text
G <= floor(1.3 * N(0))
```

其中 `N(0)` 是初始全场逆序箱数。

这个约束不要求每一步都比初始更好，只要求每个中间状态不超过总代价上限。

## 贪心主流程

入口函数：

```text
src/greedy/greedy_plan.py::plan_greedy_until_terminal
```

每一步流程：

1. 从当前仍有逆序或未良序的堆中选择候选源堆。
2. 对每个源堆，只考虑它的顶箱。
3. 枚举所有可接箱的目标堆。
4. 模拟搬移，过滤掉不合法候选：
   - 目标状态 `G` 超过上限。
   - 布局已经出现过。
5. 对剩余候选排序：
   - 优先全路径累计 `N(Future)` 更小。
   - 再优先当前 `N(Future)` 更小。
   - 再优先搬箱步数更少。
   - 多贝位时用 `drain_bay` 和 `fill_bay` 做偏置。
6. 执行动作，进入下一轮。

## 停止条件

贪心会在以下情况停止：

- 全场每堆都良序。
- 找不到满足约束的下一步动作。
- 达到 `--max-greedy-moves` 或内部保底上限。

当前样例的历史结果大多是第二种：在满足 `G` 上限的前提下已经没有可行动作，因此停止。

## 多贝位偏置

合并贝位后，程序会计算每个贝位的初始逆序箱数：

```text
bay_n0_initial
```

初始逆序多的贝位作为 `drain_bay`，初始逆序少的贝位作为 `fill_bay`。

候选动作打平时，算法倾向：

- 从 `drain_bay` 搬出。
- 往 `fill_bay` 接收。

## QUBO 精炼

QUBO 相关代码保留在：

```text
src/greedy/yard_reloc_qubo.py
src/greedy/qubo_accum.py
src/greedy/sa_solver.py
src/greedy/full_encode.py
```

设计意图是将贪心轨迹后缀放入短时间窗口，构造二次无约束二值优化问题，再用模拟退火尝试降低能量。

当前建议：

- 默认不要开启 `--refine`。
- 若要继续开发，应先统一动作元组格式、`G` 约束比例和变量规模裁剪策略。
