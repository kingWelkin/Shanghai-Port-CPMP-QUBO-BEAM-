# 结果解读

## 输出文件

默认输出目录：

```text
data/results
```

单个案例结果：

```text
result_A1_01_26_paired.txt
```

批量汇总：

```text
SUMMARY.txt
```

## 结果头部

典型头部字段：

```text
case: A1_01_26_paired
W=20 H=6 N=60
greedy_moves: 23
terminal_sorted: False
N(0)=29
G_end=43 G_cap=43 g_ok=True
combined_bays: [1, 26]
```

含义：

- `W`：全局堆数。`01+26` 合并后通常为 20。
- `H`：最大层数。当前固定为 6。
- `N`：箱数。
- `greedy_moves`：贪心执行的搬箱步数。
- `terminal_sorted`：末态是否全场良序。
- `N(0)`：初始逆序箱数。
- `G_end`：末态 `搬箱步数 + 逆序箱数`。
- `G_cap`：允许的 `G` 上限。
- `g_ok`：末态是否满足 `G <= G_cap`。

## 轨迹说明

结果中的搬箱轨迹形如：

```text
t=1 -> t=2  26-5->01-4 顶秩11 层3->层3
```

含义：

- 在第 1 步，把 `26` 贝位第 5 堆顶箱搬到 `01` 贝位第 4 堆。
- 搬的是当前源堆顶箱。
- `顶秩11` 是程序内部按关序号统一排序得到的箱秩。
- `层3->层3` 是源层到目标新顶层。

## 堆叠验收

末尾会输出每堆验收：

```text
堆26-4: 逆序 4 箱（自层2） ...
全场良序: 否
```

规则：

- `OK` 表示该堆已经满足下层关序号大于上层关序号。
- `逆序 x 箱` 表示从首个违例层开始到堆顶的非空箱数量。
- `全场良序: 是` 才代表所有堆均满足排序要求。

## 如何看当前历史结果

当前 `data/results` 中 15 个历史结果均满足 `g_ok=True`，但 `terminal_sorted=False`。

这代表：

- 算法在给定 `G` 上限内成功找到了一串合规搬箱动作。
- 这些动作降低了逆序箱数。
- 但末态仍有若干堆存在违例。

因此，报告中的 `OK` 是“程序执行成功”，不是“全场已经完全良序”。
