# Project Summary For Next-Step Algorithm Discussion

Date: 2026-06-29

This repository studies container pre-marshalling / CPMP search for Shanghai Port style layouts. The current engineering line is a compact byte-state beam search with QUBO-assisted frontier selection. QUBO is not used to generate crane moves; it only selects among already legal candidate states generated by the classical search engine.

## Hard-Case Diagnosis

The 2026-06-29 hard-case trace split failures into four mechanisms:

- BF14/BF32: compact union does not reproduce short BS-FRG recovery; successful compact rows are often long FRG seed paths.
- CV 5-8 / 6-6: micro-style local lookahead can perturb a good compact path into a longer feasible route.
- CV 10-6: the search can enter low `n`, but the retained lineage falls into a dead basin.
- CV 10-10: the search barely lowers `n`, so useful long-horizon recovery states are absent or not retained.

Do not tune another broad weight from this evidence alone. The next idea should separate path-debt avoidance from recovery-basin access.

## What The Mainline Does

At each beam layer:

1. Generate legal one-step CPMP child states with the compact classical engine.
2. Rank candidates mainly by `N` and depth, with existing v5 scheduling behavior.
3. Keep a deterministic core to protect the strongest candidates.
4. Use a small union QUBO selector to add diverse exploration candidates.
5. Repair QUBO selections to valid cardinality.
6. Continue until an `N=0` path is found or the time/frontier budget is exhausted.
7. Apply post-polish only after a valid `N=0` path exists.

The union QUBO selector combines Wang-like, FRG-like, and rollout-related signals as selection features. Its pair penalties discourage selecting candidates with the same parent, source stack, transition signature, reduce signature, or `N` band.

## Boundaries

Avoid:

- neural or data-trained policies;
- solver portfolio fallback that simply runs multiple algorithms and takes the best;
- case-name-specific gates;
- full BS-FRG as a fallback path inside the mainline;
- changes that improve one residual case while adding open120 or paper-set regressions;
- hardcoded mechanisms that cannot be ablated.

Prefer:

- ablation-friendly feature switches;
- one candidate pool and one selector path;
- paired runs against the current mainline and baseline;
- telemetry that tells whether useful children are absent, generated-but-not-selected, or selected into a dead lineage.
