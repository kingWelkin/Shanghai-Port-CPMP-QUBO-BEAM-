# Shanghai Port CPMP QUBO Beam

This repository contains engineering experiments for container pre-marshalling /
CPMP on Shanghai Port style layouts. The current v4.3 mainline combines the
chain-aware QUBO beam, bounded BS-FRG path compression, and the proven short
Wang-QUBO route behind one deterministic pre-solve policy.

## v4.3 Mainline

The promoted v4.3 variant is:

```text
qubo_scheduler_state_v5_qubo_diversity_union_unified_macro_supply_chainaware_wang_route_v43_polish
```

It supersedes the earlier v4.0 runner variant:

```text
qubo_scheduler_state_v5_qubo_diversity_union_unified_macro_supply_chainaware_polish
```

v4.3 makes one routing decision before search. Small DLTS-style layouts use the
Wang pair-QUBO and successor-cache short route. Other layouts use the v4.2
chain-aware QUBO beam with bounded BS-FRG post-compression. The route is chosen
from source semantics, layout shape, priority duplication, and initial pressure;
it is not selected after a failed solve.

## Mechanism Boundary

QUBO is used as a beam-selection helper, not as a move generator.

- Legal one-step children are generated by the compact CPMP transition engine.
- Wang-style pair/fixed-prefix features are local state quality signals.
- BS-FRG-style completion probes create bounded macro-chain candidates and can
  replace a path only when the replacement is shorter and validator-clean.
- Unified macro supply adds extra recovery-chain candidates from deeper parent
  offsets when candidate pressure is high.
- Chain-aware QUBO scoring penalizes over-reusing the same macro ancestry.
- Selected macro candidates are expanded back into compact state paths.
- Compact path gaps are repaired before lifting to physical crane moves.
- Validator replay remains the final feasibility boundary.

The practical reading: v4.3 keeps v4.0's compact QUBO-beam architecture for the
hard general surface, while recovering the much shorter Wang route on the small
open-style surface where it was already proven stronger.

## Positioning Decision

The current algorithm family is intentionally split into three roles:

- **Default mainline:** use v4.3 for Open120, full paper BF/CV, and Real30. It is
  the first recorded route with direct `1681/1681` coverage and `105530` moves.
- **v4.0 baseline:** keep the chain-aware single-profile line for ablation and
  for measuring the contribution of the v4.3 pre-solve routing policy.
- **Quality modes:** use BS-FRG post-compress profiles when shorter paths matter
  more than raw runtime. These modes start from a validated beam solution and
  only accept shorter valid recovery-chain replacements, so they are the
  practical route for CV long-path compression.
- **Research line:** keep beam-native witness quality profiles experimental.
  Asking the beam itself to preserve the future-best deep recovery chain is
  strict and fragile; those profiles should not replace v4.0 until they pass the
  full paired open120, BF, and CV gate.

The v4.1 beam-feedback candidate is:

```text
qubo_scheduler_state_v5_qubo_diversity_union_unified_macro_supply_chainaware_feedback_v41_polish
```

It keeps BS-FRG post-compress disabled and adds a conservative beam-internal
feedback credit layer: same-parent witness alternatives are compared locally,
shorter completion witnesses can receive high-confidence positive QUBO credit,
receiver debt and height risk reduce that credit, and one-layer survival credit
rewards signatures that actually produce progress in the next beam layer. The
feedback is scoped to the QUBO candidate window rather than applied as a global
reservoir pruning pass. It is experimental until full paired open120, BF, and CV
no-cap t120 evidence beats v4.0 without solved-count loss.

The first full v4.1 gate check on 2026-07-07 did **not** pass promotion:
open120 stayed solved at `120/120` but moved from the v4.0 reference `6928`
moves to `7065`; paper BF/CV solved `1558/1561`, with `BF 720/721` and
`CV 838/840`. Keep it as an experimental research profile, not a default.

Pure BS-FRG remains a path-quality teacher and reference, not the default
solver. v4.3 uses its bounded compression ideas without handing final
feasibility authority away from validator replay.

## Main Commands

Run the current open120 no-cap mainline:

```powershell
python scripts\open_cpmp_benchmarks.py --source benchmarks\open120 --no-auto-clone --families 5x5_cv1_test 5x5_cv2_test 5x5_cv3_test 7x5_cv1_test 7x5_cv2_test 7x5_cv3_test --limit-per-family 20 --variant qubo_scheduler_state_v5_qubo_diversity_union_unified_macro_supply_chainaware_wang_route_v43_polish --time-limit 120 --alpha 10 --jobs 8 --no-business-cap --output docs\experiments\v43_open120_t120.csv
```

Run the full paper BF/CV no-cap gate:

```powershell
python scripts\benchmark_compact_paper_set.py --source benchmarks\paper --datasets BF CV --sample-per-family 9999 --variant qubo_scheduler_state_v5_qubo_diversity_union_unified_macro_supply_chainaware_wang_route_v43_polish --time-limit 120 --alpha 10 --jobs 8 --no-business-cap --output docs\experiments\v43_paper_bf_cv_full1561_t120.csv
```

The tracked [benchmark corpus](benchmarks/README.md) contains the exact
Open120 inputs and references plus all 721 BF and 840 CV instances used by the
v4.3 promotion gate. The larger upstream clones under `external/` remain local
and ignored.

Run focused regression tests:

```powershell
$env:PYTHONPATH='.'; $env:PYTEST_DISABLE_PLUGIN_AUTOLOAD='1'; python -m pytest tests\test_qubo.py tests\test_bs_frg_paper_benchmarks.py tests\test_current_mainline_union.py -q
```

Compile-check the benchmark entrypoints:

```powershell
$env:PYTHONPATH='.'; python -m py_compile scripts\benchmark_compact_beam_qubo_n0.py scripts\open_cpmp_benchmarks.py scripts\benchmark_compact_paper_set.py
```

- `src.zip` is treated as a local artifact unless explicitly requested for
  packaging.
- Gurobi is not required for the current QUBO beam mainline.
- Promotion decisions must report open120, BF, and CV separately.
- Historical 30-case `speed_v2` results remain useful for internal-regression
  context, but the current v4.3 promotion gate gives Open120, BF, and CV equal
  solved-count priority.
